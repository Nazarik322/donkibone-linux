# Celestia — CachyOS + caelestia: установочная флешка

Celestia — это CachyOS (её ядро, драйверы, оптимизации — без изменений) с оболочкой
[caelestia](https://github.com/caelestia-dots/caelestia) на Hyprland. Оформление CachyOS убрано.

Ставится как Windows: загрузился с флешки → выбрал, куда ставить → имя и пароль → готово.
Интернет при установке не нужен.

После установки при каждом включении ПК:

1. **Меню выбора системы** в стиле Celestia. Через 5 секунд загружается **Windows**;
   стрелками ← → выбираешь **Celestia**, Enter.
2. Тихая загрузка Linux.
3. **Экран блокировки Celestia**: вводишь пароль — рабочий стол.
   (Первую секунду-две после загрузки виден простой экран блокировки hyprlock — он закрывает
   сеанс, пока запускается оболочка, затем его сменяет экран Celestia.)

Если Windows на компьютере нет, по умолчанию загружается Celestia.

## 1. Требования

**Компьютер, на который ставим:**

| | |
|---|---|
| Режим загрузки | **UEFI** (все ПК примерно с 2012 года). Старый режим Legacy/BIOS не поддерживается |
| Процессор | 64-битный Intel/AMD. Сборка по умолчанию требует **x86-64-v3** (Intel Haswell 2013+, AMD Zen/Excavator+). Для старых процессоров собери с `CACHYOS_MARCH="generic"` (см. [п. 2](#2-сборка-iso)) |
| Место | не меньше **30 ГБ**, рекомендуется 60+ ГБ |
| Память | 4 ГБ ОЗУ и больше |
| Видеокарта | любая: NVIDIA, AMD, Intel — драйвер ставится автоматически |

**Компьютер, на котором собираем ISO** (может быть тот же самый):

- Windows 10/11 с WSL2 **или** любой Linux на базе Arch (Arch, CachyOS, EndeavourOS…);
- ~60 ГБ свободного места, 8+ ГБ ОЗУ, интернет;
- флешка от **8 ГБ** (будет полностью стёрта).

## 2. Сборка ISO

### 2.1. Подготовка (один раз)

**На Windows.** Открой PowerShell **от имени администратора**:

```powershell
wsl --install archlinux
```

Перезагрузи компьютер, если попросит. Открой Arch (`wsl -d archlinux` или «Arch Linux» в меню Пуск),
придумай имя пользователя и пароль. Дальше все команды — внутри Arch.

**На Arch/CachyOS** — просто открой терминал.

Перейди в папку проекта (на Windows диск `C:` виден как `/mnt/c`) и запусти подготовку:

```bash
cd /mnt/c/путь/к/donkibone-linux
sudo ./scripts/setup-build-env.sh
```

Скрипт подключит репозитории CachyOS (официальным скриптом CachyOS — на вопросы отвечай `y`)
и установит инструменты сборки. Если в конце он попросит включить systemd в WSL — добавь в
`/etc/wsl.conf` указанные строки, выполни в Windows `wsl --shutdown` и открой Arch заново.

### 2.2. Настройки (по желанию)

Файл `config.env`:

| Параметр | Что значит |
|---|---|
| `CACHYOS_MARCH` | `v3` — быстрее, но нужен процессор x86-64-v3; `generic` — работает на любом 64-битном процессоре |
| `DEFAULT_TIMEZONE_REGION` / `ZONE` | часовой пояс, выбранный в установщике по умолчанию (можно поменять при установке) |

Как проверить процессор: в Linux `/lib/ld-linux-x86-64.so.2 --help | grep v3`
(есть строка `x86-64-v3 (supported...)` — подходит `v3`). В Windows: если процессор
Intel Core 4-го поколения и новее или любой AMD Ryzen — подходит `v3`.

### 2.3. Сборка

```bash
./build.sh
```

Первая сборка — час и больше (собираются пакеты из AUR, скачивается ~4 ГБ), повторные быстрее.
Результат: `out/celestia-ГГГГ.ММ.ДД-x86_64.iso` и файл контрольной суммы `.sha256`.

Каждый запуск собирает образ заново (скачанные пакеты берутся из кэша).
`./build.sh --clean` — дополнительно пересобрать с нуля все собственные и AUR-пакеты
(если сборка пакетов сломалась или нужно обновить зависимости из AUR).

## 3. Запись на флешку

Все данные на флешке будут удалены.

- **Windows — [Rufus](https://rufus.ie):** выбери флешку и ISO → «Старт» → когда спросит
  режим записи, выбери **«Записать в режиме DD-образа»**.
- **Windows/macOS/Linux — [balenaEtcher](https://etcher.balena.io):** Flash from file → флешка → Flash.
- **Linux:** `sudo dd if=celestia-*.iso of=/dev/sdX bs=4M status=progress oflag=sync`
  (`/dev/sdX` — именно флешка, проверь через `lsblk`!).
- **Ventoy:** в нём есть пункт меню для загрузки через `loopback.cfg`, но этот путь не проверялся —
  если что-то не так, используй запись в режиме DD.

## 4. Подготовка компьютера

### 4.1. В Windows (если она установлена)

| Что | Зачем | Как |
|---|---|---|
| **Резервная копия важных файлов** | Установщик не трогает Windows, но страховка нужна всегда | Внешний диск или облако |
| **Освободить место** (если ставишь на тот же диск) | Celestia ставится в неразмеченное место | `Win+X` → «Управление дисками» → правый клик по `C:` → «Сжать том» → указать размер (от 30 000 МБ, лучше 60 000+). Получившееся «Не распределено» **не форматируй** |
| **Ключ BitLocker** (если включено шифрование) | После установки Windows может один раз попросить ключ восстановления | Ключ: [aka.ms/myrecoverykey](https://aka.ms/myrecoverykey) или «Панель управления» → «Шифрование диска BitLocker» → «Архивировать ключ». Проверить шифрование: «Параметры» → «Конфиденциальность и защита» → «Шифрование устройства» |
| **Выключить «Быстрый запуск»** | Иначе диски Windows в Linux будут доступны только для чтения, а время может сбиваться | «Панель управления» → «Электропитание» → «Действия кнопок питания» → «Изменение параметров, которые сейчас недоступны» → снять «Включить быстрый запуск» |

Если Celestia ставится на **отдельный пустой диск**, сжимать ничего не нужно.

### 4.2. В BIOS/UEFI

Вход в BIOS: при включении нажимай **Del** или **F2** (ноутбуки: F2, F1, F10, Esc).

| Настройка | Значение | Почему |
|---|---|---|
| **Secure Boot** | **Disabled** (выключить) | Меню загрузки Celestia не подписано. На Windows это не влияет |
| **Boot Mode / CSM** | **UEFI** (CSM — Disabled) | Celestia работает только в UEFI |
| **Fast Boot** (быстрая загрузка BIOS) | Disabled | Иначе BIOS может не увидеть флешку |
| **SATA Mode** | **AHCI** | В режиме RAID/Intel RST Linux не видит диски. ⚠️ Если там стоит RAID/RST, а Windows уже установлена, переключение сломает загрузку Windows — сначала поищи «переключение RAID на AHCI Windows безопасный режим» |

Если Windows установлена в старом режиме (Legacy/MBR), установщик это заметит и
предупредит: меню выбора не сможет её запускать, только меню загрузки BIOS.

### 4.3. Загрузка с флешки

Вставь флешку и при включении ПК открой **меню загрузки** — выбери флешку с пометкой **UEFI**:

| Производитель | Клавиша | | Производитель | Клавиша |
|---|---|---|---|---|
| ASUS | F8 (ноутбуки — Esc) | | Lenovo | F12 (или кнопка Novo) |
| MSI | F11 | | HP | F9 (или Esc) |
| Gigabyte | F12 | | Dell | F12 |
| ASRock | F11 | | Acer | F12 |

## 5. Установка

1. **Меню флешки** → «Установить Celestia» (запустится само через 5 секунд).
   Чёрный экран или зависание — перезагрузись и выбери **«Установить Celestia (безопасная графика)»**.

2. **Окно «Куда установить Celestia».** Здесь видны все диски и разделы компьютера:

   | Строка | Что произойдёт |
   |---|---|
   | **Свободное место — N ГБ** | Celestia ставится в неразмеченное место. **Ничего существующего не меняется.** Обычный выбор рядом с Windows |
   | **Раздел Linux …** | Старый раздел Linux стирается, на его месте ставится Celestia. Остальное не меняется |
   | **Предыдущая установка Celestia …** | Разделы прошлой (или прерванной) установки Celestia стираются все сразу, Celestia ставится заново |
   | **Весь диск …** | Диск стирается целиком. Предлагается только для дисков, где нет Windows и данных |
   | 🔒 **…** | Windows, BitLocker, данные (NTFS, exFAT, FAT), загрузчик Windows (и EFI-разделы, которые не удалось проверить), диски RAID (в т. ч. Intel RST) / LVM / шифрования, диски с файловой системой без таблицы разделов, сама флешка, используемые разделы. **Выбрать нельзя** |

   После выбора появится сводка: что будет сделано и что останется нетронутым.
   Если что-то будет стёрто, нужно ввести слово **ERASE** — случайно нажать не получится.

3. **Установщик:** язык и часовой пояс → раскладка (её же получит рабочий стол) →
   имя пользователя и пароль (от 4 символов) → «Установить».
   Чтобы выбрать другое место, закрой установщик — снова откроется окно выбора диска.

4. В конце — «Перезагрузить». **Вытащи флешку.**

### Как установщик защищает Windows и данные

- Разделы Windows, разделы с данными, зашифрованные разделы, загрузчик Windows, члены RAID/LVM
  и флешка **никогда не предлагаются** для установки. Всё, что не удалось однозначно опознать,
  считается занятым.
- Перед записью установщик **заново проверяет диск**. Если что-то изменилось с момента
  выбора — установка останавливается, **ничего не записав**.
- Каждый новый раздел проверяется: он должен быть внутри выбранного места и не пересекаться
  ни с одним существующим.
- После разметки установщик **сверяет все остальные разделы** — они должны остаться точно
  такими же. Если нет — установка прерывается с сообщением.
- Загрузочный раздел Windows (EFI) не форматируется: туда только добавляется папка меню
  загрузки (~3 МБ). Если места на нём мало, Celestia создаёт свой EFI-раздел в выбранном месте.

Если Celestia ставится на **другой диск**, чем Windows, меню всё равно найдёт Windows.

## 6. После установки

| Что | Как |
|---|---|
| Меню приложений | Super (клавиша Windows) |
| Терминал / браузер / файлы | Super+T / Super+W / Super+E |
| Закрыть окно | Super+Q |
| Блокировка | Super+L |
| Меню выключения | Ctrl+Alt+Delete |
| Смена раскладки | Alt+Shift (если в установщике выбрано несколько раскладок) |
| Все горячие клавиши | [caelestia: Default keybinds](https://github.com/caelestia-dots/caelestia#default-keybinds) |
| Обновить систему | `celestia-update` в терминале |
| Свои настройки Hyprland | `~/.config/caelestia/hypr-user.lua` и `hypr-vars.lua` |
| Настройки оболочки | `~/.config/caelestia/shell.json` |
| Обои | `~/Pictures/Wallpapers` |

**Обновления:** `celestia-update` в терминале. Подробности, каналы stable / beta / dev и что
значит «Qt придержан» — в [п. 6.1](#61-обновления-и-каналы).

**Снимки и откат.** Перед и после каждой установки/обновления пакетов создаётся снимок системы
(snapper, до 10 штук; папка `/home` в снимки не входит). Если после обновления что-то сломалось —
открой **Btrfs Assistant** → «Snapper» → выбери снимок → «Restore» и перезагрузись. Если рабочий
стол не запускается, войди через «Recovery» (см. п. 7) и выполни `sudo btrfs-assistant` либо
`sudo snapper list` / `sudo snapper undochange`.

Диски Windows должны быть видны в файловом менеджере Thunar (gvfs + udisks); на реальном железе
это не проверялось.

### 6.1. Обновления и каналы

Всё «наше» (оболочка caelestia, quickshell, настройки Celestia, ключ подписи) приходит
обычными пакетами pacman из подписанного репозитория на GitHub; остальное — из CachyOS, как
обычно. Установка с флешки по-прежнему работает без интернета: сеть нужна только для обновлений.

| Команда | Что делает |
|---|---|
| `celestia-update` | Обновляет систему и пакеты Celestia, затем подтягивает новые версии настроек в домашней папке |
| `celestia-channel` | Показывает текущий канал |
| `sudo celestia-channel beta` | Переключает канал (stable / beta / dev) и сразу синхронизирует пакеты |

**Каналы.** Канал выбирается при сборке ISO по ветке git и меняется командой выше:

| Канал | Для чего | Из ветки |
|---|---|---|
| `stable` | Проверенные версии. Для обычной работы | `main` |
| `beta` | Новое, что уже опробовано, но ещё не выпущено | `beta` |
| `dev` | Свежие сборки разработки, возможны поломки | `dev` |

При переходе на более старый канал (например, `dev` → `stable`) пакеты Celestia откатываются
до его версий; перед этим автоматически делается снимок системы.

**Qt придерживается.** Оболочка собрана под конкретную версию Qt из CachyOS. Если CachyOS
выпустил новый Qt раньше, чем оболочка пересобрана под него (пересборка запускается
автоматически и обычно занимает меньше часа), `celestia-update` ничего не обновит и скажет
подождать; рабочий стол продолжит работать. Обычный `pacman -Syu` в этот момент тоже
откажется обновлять Qt, а не сломает систему.

**Настройки в домашней папке.** Файлы caelestia (`~/.config/hypr`, `fish`, `foot` и др.)
обновляются вместе с системой, но **только если ты их не менял**. Изменённый файл остаётся как
есть, а новая версия кладётся рядом как `ИМЯ.celestia-new` (список —
`~/.local/state/celestia/dots-conflicts.txt`): сравни и перенеси нужное. Твои собственные файлы
(`hypr-user.lua`, `hypr-vars.lua`, `user-config.fish`, `shell.json`) не трогаются никогда.

**Безопасность.** Репозитории подписаны ключом (в пакете `celestia-keyring`); pacman не
установит ничего без верной подписи.

### Ограничения

- **Нет шифрования диска** (LUKS) и **нет гибернации** (swap не создаётся, используется zram):
  клавиша сна (Super+Shift+L) — обычный сон; при критическом заряде ноутбук корректно выключается.
- **Драйверы при установке ставятся только для видеокарты** (офлайн). Остальное оборудование,
  которому CachyOS ставит отдельные пакеты (сканеры отпечатков, Broadcom Wi-Fi и т. п.),
  настраивается после установки при наличии интернета: `sudo chwd -a`.
- **NVIDIA:** поддерживаются карты GTX 16xx / RTX (открытый драйвер). Более старые
  (GTX 9xx/10xx) работают на свободном драйвере nouveau — медленнее.
- **Secure Boot** не поддерживается; **Legacy/BIOS** не поддерживается.
- Если прошивка игнорирует загрузочные записи UEFI (бывает на некоторых ноутбуках HP/Lenovo),
  Celestia придётся выбирать через меню загрузки BIOS — запасной загрузчик не ставится, чтобы
  не перехватить загрузку Windows.
- Для обновлений нужен интернет и доступ к github.com.
- Интерфейс установщика и меню — на русском языке.

## 7. Если что-то пошло не так

| Проблема | Решение |
|---|---|
| Флешка не видна в меню загрузки | Выключи Fast Boot в BIOS; выбери пункт с пометкой «UEFI»; перезапиши флешку в режиме DD |
| Флешка не запускается (ошибка Secure Boot / «Security violation») | Выключи Secure Boot |
| Флешка зависает сразу после выбора пункта, без надписей | Процессор не поддерживает x86-64-v3 — собери ISO с `CACHYOS_MARCH="generic"` |
| Чёрный экран при запуске установщика | Пункт «безопасная графика» |
| «Не найдено подходящего места» | Освободи 30+ ГБ в Windows («Сжать том»), см. [п. 4.1](#41-в-windows-если-она-установлена) |
| Не видно дисков | SATA Mode в BIOS стоит RAID/RST — см. [п. 4.2](#42-в-biosuefi) |
| Сразу грузится Windows, меню нет | Обновление Windows перехватило загрузку. Загрузи Celestia через меню загрузки BIOS (F8/F11/F12) и выполни `sudo celestia-refind --fix-order` |
| Пропало оформление меню / меню сломалось | `sudo celestia-refind` |
| Чёрный экран после обновления | В меню выбора выбери Celestia и нажми **F2** → «Recovery», войди и выполни `celestia-update`; не помогло — откати снимок (п. 6) |
| После входа сразу снова экран входа (текстовый) | Не запустился ни один экран блокировки — сеанс завершён ради безопасности. Войди здесь же и выполни `celestia-update` |
| Не работают Wi-Fi Broadcom / сканер отпечатка | Подключись к интернету по кабелю и выполни `sudo chwd -a` |
| Windows просит ключ BitLocker | Введи ключ восстановления (см. [п. 4.1](#41-в-windows-если-она-установлена)), это бывает один раз |
| Время в Windows сбивается | Не должно (Celestia держит часы в локальном времени, как Windows). Если всё же — выключи «Быстрый запуск» |
| После включения Secure Boot Linux не грузится | Это ожидаемо: выключи Secure Boot обратно |

Журнал установки: `/root/.cache/calamares/session.log` в live-среде (Ctrl+Alt+F2 — консоль).

## 8. Удаление Celestia

1. В Windows: `Win+X` → «Управление дисками» → удали разделы Celestia
   (обычно 2 ГБ + основной, без буквы диска) → освободившееся место можно присоединить к `C:`
   («Расширить том»).
2. Убери меню загрузки. PowerShell от администратора:
   ```powershell
   mountvol S: /s
   Remove-Item -Recurse S:\EFI\refind
   mountvol S: /d
   bcdedit /enum firmware      # найди запись "Celestia" и её {идентификатор}
   bcdedit /delete {идентификатор}
   ```
3. Перезагрузи — сразу загрузится Windows.

Если Celestia ставилась со своим EFI-разделом (метка `CELESTIA`), удали и его.
Переустановить Celestia можно с флешки: в окне выбора будет строка «Предыдущая установка Celestia».

## 9. Для разработчика

### Как устроено

```
build.sh                    вся сборка одной командой
config.env                  настройки сборки
packages/system.txt         состав установленной системы (база CachyOS + Hyprland + caelestia)
packages/live.txt           только для флешки, удаляется при установке
packages/drivers.txt        драйверы для офлайн-установки (по профилям CachyOS chwd)
pkgbuilds/                  закреплённые версии caelestia-shell, caelestia-cli, quickshell,
                            m3shapes, темы Firefox; celestia-system — наши настройки
calamares/                  установщик: шаги, модуль разметки celestiadisk, скрипты, брендинг
profile/                    профиль archiso (на основе CachyOS-Live-ISO): меню флешки, live-среда
profile/airootfs/usr/local/bin/
    celestia-installer      запуск live-сессии (cage, на весь экран)
    celestia-diskpick       окно выбора места установки
    celestia-disks          поиск безопасных мест и разметка (с проверками)
theme/palette.env           палитра Celestia (схема caelestia по умолчанию)
scripts/                    этапы сборки
tests/                      проверки без root и без дисков: bash tests/run-all.sh
```

Этапы `build.sh`:

1. `scripts/make-theme.sh` — рисует оформление (меню загрузки, меню флешки, установщик, обои).
2. `scripts/build-packages.sh` — собирает в чистом chroot всё, чего нет в репозиториях
   (закреплённые PKGBUILD из `pkgbuilds/` и зависимости из AUR).
3. `scripts/fetch-offline-repo.sh` — кладёт на флешку драйверы для офлайн-установки.
4. `mkarchiso` собирает ISO (каждый раз с чистым рабочим каталогом).

Перед сборкой `scripts/check-consistency.sh` сверяет продублированные закрепления версий;
одновременно может идти только одна сборка.

### Проверки

```bash
bash tests/run-all.sh
```

`bash -n` (и shellcheck, если установлен), сверка версий, тесты безопасности разметки
(`tests/test_celestia_disks.py`), экрана блокировки (`tests/test_session_start.sh`) и
загрузочных записей UEFI (`tests/test_celestia_refind_nvram.sh`).

### Обновление версий caelestia

Версии закреплены, чтобы сборка всегда давала проверенную связку:

- `pkgbuilds/caelestia-shell/PKGBUILD`, `pkgbuilds/caelestia-cli/PKGBUILD` — `pkgver` и `sha256sums`
  (как в AUR-пакетах `caelestia-shell`, `caelestia-cli`); версию оболочки — также в `scripts/make-theme.sh`;
- `pkgbuilds/quickshell-git`, `pkgbuilds/qt6-m3shapes-git` — `_commit`;
- `pkgbuilds/celestia-system`, `pkgbuilds/caelestia-firefox-theme` — `_dots_commit`.

Пакеты из AUR (зависимости) берутся с последнего коммита. Рядом с каждым ISO сохраняется
`*.aur.lock` с использованными коммитами — скопируй его в `packages/aur.lock`, и следующие
сборки возьмут ровно их (для `--clean` и других машин).

### Репозиторий, ветки и выпуск обновлений

Проект — публичный репозиторий <https://github.com/Nazarik322/donkibone-linux>:

```
feature/*  ──PR──▶  dev  ──PR──▶  beta  ──PR──▶  main
                     │             │             │
                  [celestia-dev] [celestia-beta] [celestia-stable]   (подписанные репозитории pacman)
```

- Каждый push в `dev` / `beta` / `main` запускает **packages** (GitHub Actions): собирает пакеты
  в контейнере Arch + CachyOS, подписывает и публикует их в релиз `repo-<канал>`. Пакеты, у
  которых ничего не изменилось, берутся из прошлого релиза.
- **tests** запускается на каждый push и PR (`bash tests/run-all.sh`).
- **qt-watch** раз в час сверяет Qt в CachyOS с тем, под который собраны пакеты, и запускает
  пересборку, если он сменился.
- **iso** (вручную: Actions → iso → Run workflow, выбрать ветку) собирает ISO из пакетов канала
  и прикладывает его к запуску на 7 дней. Локально то же самое: `CELESTIA_RESTORE=1 ./build.sh`.
- Версии собственных пакетов: `1.<число коммитов>` (`celestia-system`), для оболочки — как в PKGBUILD.

Разовая настройка (уже сделана для этого репозитория): секрет `CELESTIA_SIGNING_KEY` — закрытый
ключ подписи в формате `gpg --armor --export-secret-keys`; открытая часть и отпечаток лежат в
`keys/` и в пакете `celestia-keyring`. Закрытый ключ хранится только в секретах репозитория
и в твоей резервной копии, **в репозиторий его класть нельзя**. Если ключ придётся заменить —
выпусти новый `celestia-keyring` (подписанный старым ключом) до замены.

### Проверка в виртуалке

Hyper-V (поколение 2, Secure Boot выключен) или VirtualBox с включённым EFI: поставь Windows,
оставь неразмеченное место, затем загрузись с ISO. Проверь: в окне выбора Windows-разделы
под 🔒; Windows по умолчанию через 5 с; Celestia по стрелкам; экран блокировки; звук и сеть.
